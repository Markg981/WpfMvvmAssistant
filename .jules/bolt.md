## 2024-05-24 - [Regex Pattern Compilation Strategy]
**Learning:** In `RuleBasedNaturalLanguageTranslator`, caching static patterns ('top', 'first', 'last X days') with `RegexOptions.Compiled` yields massive (~90%) performance gains by avoiding recompilation overhead. However, dynamic patterns that vary based on loop variables (like matching dynamic column names inside `FindConditions`) MUST continue to use standard `Regex.Match` instead of being compiled on the fly. Compiling dynamic strings inside loops is a severe performance anti-pattern that destroys performance due to massive GC pressure and repeated IL generation overhead.
**Action:** When optimizing regex matching, always separate static and dynamic patterns. Pre-compile static patterns as static readonly fields, but leave dynamic per-iteration patterns uncompiled.
