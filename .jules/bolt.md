## 2026-04-16 - Static vs Dynamic Regex Compilation Overhead in NLP Translator
**Learning:** Compiling dynamic regex patterns inside a loop using `RegexOptions.Compiled` is a severe performance anti-pattern that destroys performance due to massive GC pressure and repeated IL generation overhead. Conversely, using pre-compiled static regexes (`private static readonly Regex`) with `RegexOptions.Compiled` for static patterns provides significant performance benefits (around 90% faster) compared to recreating the pattern repeatedly inside parsing loops.
**Action:** Always extract static regex patterns out of parsing loops and define them as `private static readonly Regex` instances with `RegexOptions.Compiled`. Keep dynamic regex patterns (e.g., those using variable string interpolation) as standard `Regex.Match` calls without compilation to avoid the overhead of generating uncollectible MSIL on the fly.
